# Markdown Conventions for EI Graphics Planning Docs

Use these conventions to keep planning artifacts consistent and reviewable.

## File naming

- Use lowercase with hyphen separators.
- Use explicit names for intent: plan.md, todo-list.md, current-status.md.

## Headings

- Use H1 once per document.
- Use H2/H3 for sections and sub-sections.
- Keep headings concise and action-oriented.

## Task tracking

- Prefer tables for task dashboards.
- Include explicit status and owner for each task.
- Do not remove completed tasks; mark as Done.

## Decision records

- Use unique IDs (for example: D-001).
- Include status, date, decision, and rationale.

## Status updates

- Add date-stamped updates in progress-log.md.
- Keep entries factual and traceable to actions.
- Capture both completed work and next planned action.

## Safety and governance notes

- Call out assumptions explicitly.
- Separate accepted decisions from open questions.
- Record risk and mitigation together in one place.

## Writing style

- Prefer short, concrete sentences.
- Avoid vague wording (for example: soon, maybe, probably).
- Use consistent domain terms once ontology definitions are approved.
