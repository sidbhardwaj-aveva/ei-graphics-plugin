**Purpose:** Evidence-backed workflow discovery and workflow redesign recommendations for engineering workflow refinement and future Copilot plugin design.

## 2. Workflow Mismatches and Gaps

### Incomplete / Missing

| Gap | Evidence | Risk |
|-----|----------|------|
| **No integration tests in EI module** | All 24 test projects are unit tests; `Aveva.EI.Repositories.TestAddIn` references `MockFramework` but is isolated | Domain logic interacting with DB is only tested at PR sanity (late feedback) |
| **No code coverage measurement** | No `.coverlet*`, `coverlet.runsettings`, or coverage report config | Cannot identify untested code paths; regressions hide in coverage gaps |
| **No architecture enforcement** | `Commands` references `UI` (cross-layer); no ArchUnit, NDepend, or layer tests | Architecture will continue to degrade without gates |
| **Design docs only in Visio** | 5 `.vsdx` files, no text-based documentation | Cannot be reviewed in PRs, searched, or version-compared |
| **389 TODO/HACK/FIXME comments** | Files marked "needs to be deleted" since ClearCase era still present; hardcoded values | Technical debt is invisible to planning; no triage process |
| **No CONTRIBUTING guide** | No onboarding docs, no PR checklist, no architectural decision records | Knowledge is tribal; contractors onboard slowly |

### Inconsistent

| Inconsistency | Evidence | Impact |
|---------------|----------|--------|
| **Test naming varies** | 4 different naming conventions across test projects | Harder to find/understand tests; no standard to enforce |
| **DI pattern fragmented** | `ServiceFactory` (Activator.CreateInstance) vs `DependencyResolver` (service locator) vs constructor params | Unpredictable dependency resolution; testing friction |
| **Error handling catches `Exception`** | 51 `catch (Exception` matches across 20 files | Swallows unexpected errors; masks bugs in production |
| **Deprecated code coexists** | 17+ `[Obsolete]` methods in ModelGateway kept alive; dead files from ClearCase | Cognitive load; risk of calling deprecated paths |
| **`x64/Debug/` folders committed** | `DomainServices/x64/Debug/ScriptService.cs` duplicates | Build artifacts in source control |

### Manual / Fragile

| Area | Evidence | Fragility |
|------|----------|-----------|
| **Local environment setup** | `launcheng.bat` hardcodes `d:\git\dabacon-products\Core\PDMSUI` and 20+ project paths | Breaks on any machine with different layout |
| **Version generation** | Perl script (`buildres.pl`) generates `SolutionInfo.cs` | External toolchain dependency; not reproducible locally without full build env |
| **Test resolution** | `%PRODUCTINSTALL%\%VBIN%\` in runsettings | Tests require full product installation; cannot run in isolated container |
| **Performance tracing** | Environment variable toggle → `ConsoleLogger` output | No structured metrics; no baseline comparison; no alerting |

### Weak Handoffs

| Handoff | Gap |
|---------|-----|
| Bug diagnosis → implementation | No structured reproduction steps template; developer must re-derive context from ADO description |
| Implementation → test | No test coverage gate; developer decides test scope |
| Unit test → regression test | Test categories (`PRValidation_EIGSanity`) are in a separate repo; no local way to run sanity checks |
| Developer → reviewer | No PR template; no checklist for architectural impact |

## 3. Recommended Workflow Refinement

### Must-Have Changes

1. **Add a PR template** with checklist: ADO link, test coverage rationale, architecture layer check, no new `catch (Exception)`, no new TODOs without ADO tracking.
   - *Evidence basis:* No PR template exists; cross-layer violations and bare catches continue accumulating.

2. **Introduce architecture tests** (e.g., NetArchTest or NDepend rules): `Commands` must not reference `Presentation` projects; `DomainServices` must not reference `Presentation`.
   - *Evidence basis:* `Commands.csproj` references `Aveva.EI.3DPanelDesign`, `Aveva.EI.UI`, `Aveva.EI.CoreDependentUI`.

3. **Enforce test naming standard** — pick one (`Method_Scenario_Expected`) and lint for it.
   - *Evidence basis:* 4 conventions coexist; inconsistency makes test discovery unreliable.

4. **Add integration test project** for critical paths (wiring rules, cable termination, power distribution) using `MockFramework` at the repository boundary.
   - *Evidence basis:* Only unit tests exist; regression caught at PR sanity (late, expensive, opaque).

### Should-Have Improvements

5. **Convert design docs to Mermaid/markdown** so they can be reviewed in PRs and searched.
   - *Evidence basis:* Visio files cannot be diffed or reviewed in ADO.

6. **Implement code coverage with minimum threshold** (e.g., 60% floor, 80% new code target).
   - *Evidence basis:* Zero coverage tooling; no way to identify untested code.

7. **Create a TODO/tech-debt triage process** — each TODO gets an ADO item or is deleted.
   - *Evidence basis:* 389 comments spanning years; some reference ClearCase (migrated ~2018+).

8. **Standardize DI** — migrate `ServiceFactory` to proper container registration.
   - *Evidence basis:* `Activator.CreateInstance` in ServiceFactory silently returns `default(T)` on failure — bugs hide behind null references.

### Later-Phase Optimizations

9. **Containerize test execution** — remove `%PRODUCTINSTALL%` dependency for unit tests.
10. **Replace `PerformanceTracing`** with OpenTelemetry structured tracing.
11. **Automated dead-code detection** — remove files marked "to delete" since ClearCase.
12. **Local PR sanity subset** — allow developers to run `EIGSanity` category tests before pushing.

## 4. Automation Opportunities

| Workflow Step | Human-Led | Copilot-Supported | Deterministic (Automated) | Hard-Block Gate |
|--------------|-----------|-------------------|---------------------------|-----------------|
| **Bug intake** | Triage priority, customer context | Draft reproduction steps from SR description | ADO work item creation with template fields | — |
| **Diagnosis** | Root cause reasoning, debugging | Search codebase for related patterns, show recent changes to affected area | — | — |
| **Implementation** | Design decisions, algorithm choice | Generate boilerplate (new Command, ViewModel, test scaffolding); suggest layer-correct project | Architecture layer lint (fail on cross-layer reference) | Layer violation in PR |
| **Unit testing** | Test scenario design | Generate test method stubs from method signatures; suggest missing coverage | Run test suite; coverage threshold check | Coverage below floor |
| **PR creation** | Writing description | Auto-fill PR template, link ADO items, summarize changes | Pre-PR local lint (StyleCop, analyzers, layer tests) | Required fields missing |
| **Code review** | Architectural judgment, domain correctness | Flag bare `catch(Exception)`, new TODOs, naming violations, cross-layer references | Automated review checks (formatting, naming, security) | Sanity pipeline failure |
| **Regression testing** | Exploratory testing, edge cases | — | PR sanity pipeline (`EIGSanity`) | Pipeline red |
| **Release** | Go/no-go decision, cherry-pick selection | Changelog draft from merged PR titles | Version bumping, installer packaging | — |

### Where Automation Would Be Dangerous

- **Auto-fixing domain logic** — Electrical engineering calculations (cable sizing, voltage validation, phase naming) require SME review. Incorrect wiring rules can cause real-world safety issues.
- **Auto-merging PRs** — Given the monorepo with 239 contributors, unreviewed merges risk cross-discipline breakage.
- **Auto-deleting "obsolete" code** — Files marked for deletion may still be referenced via reflection or PML scripting not visible in static analysis.

## 6. Domain Glossary

| Term | Definition (from repo evidence) | Source |
|------|------|--------|
| **Cable** | Physical connection between equipment; has cores, glands, lugs, catalogue reference, estimated length | `Cable.cs`, `CableAttributeUris.cs` |
| **Core** | Individual conductor within a cable; has from-end and to-end terminations | `Core.cs`, `FromCoreEnd.cs`, `ToCoreEnd.cs` |
| **Wiring Rule** | Template defining how cables/cores connect between equipment types; applied to create wiring automatically | `WiringRule.cs`, `WiringRuleService.cs` |

| **Enclosure** | Physical housing for electrical equipment; has compartments, accessories, misc parts | `Enclosure.cs`, `EnclosureInstanceService.cs` |
| **Terminal Arrangement** | Ordered set of connection points on equipment; mapped from library types | `TerminalArrangement.cs`, `TerminalArrangementService.cs` |
| **Canvas Drawing** | Schematic diagram representation (SLD, termination drawing, block diagram) | `CanvasDrawingsService.cs`, `DrawingController.cs` |
| **Termination Drawing** | Specific canvas showing how cables/cores terminate on equipment | `TerminationDrawing/` folder in CanvasDrawings |
| **SLD** | Single Line Diagram — power distribution schematic | Commit: "Application Displays Error When Default SLD Symbol Is Missing" |

| **DbElement** | Core database entity in AVEVA's DataModelling system; domain objects materialize from these | `DbElementDataSource.cs`, `IDataSource` |
| **Pseudo (DbPseudo)** | Computed/virtual attribute derived from real database values; presented as if stored | `DbPseudos/` project, `PseudoBase.cs` |

| **SGC** | Schematic Graphics Client — canvas/drawing subsystem | Pipeline: `SGCSanity`, project: `SGCClient/` |
| **PML** | Programmable Macro Language — scripting for E3D platform | `Documents/PML/`, `pdmsui` env var |
| **E3D / Everything3D** | Host desktop application; EI is a loadable addin module | `engineering.bat`, addin pattern |

## 7. Risk and Blast-Radius Map

### High-Risk / High-Connectivity Modules

```
┌────────────────────────────────────────────────────────────────┐
│  Commands (100+ commands)                                       │
│  ├── References DomainServices (expected)                       │

│  ├── References DomainModels, Repositories, Vocabulary          │
│  └── Cross-referenced internally via ServiceFactory             │
├────────────────────────────────────────────────────────────────┤
│  ModelGateway — SINGLETON, CRITICAL BLAST RADIUS               │
│  ├── All data access depends on this                            │
│  └── 17+ deprecated methods still potentially active            │
├────────────────────────────────────────────────────────────────┤
│  CanvasDrawings — HIGHEST DEBT (40+ TODOs)                     │

└────────────────────────────────────────────────────────────────┘
```

### Blast-Radius Assessment

| Module | Blast Radius | Evidence | Recommendation |
|--------|-------------|----------|----------------|
| **`ModelGateway`** | CRITICAL — affects all data access | Singleton; all repos depend on it; deprecated methods still active | Any change requires full regression; add integration tests first |
| **`DomainServices`** | HIGH — 70+ services, cross-referenced via ServiceFactory | `ConnectedItemService` alone has 17 ServiceFactory calls | Changes cascade; require domain + UI test coverage |
| **`Vocabulary` (ClassUris, AttributeUris)** | HIGH — schema contract between domain and persistence | Changing a URI constant breaks data loading for entire entity type | Hard-block on vocabulary changes without migration plan |
| **`CanvasDrawings`** | HIGH — 40+ TODOs, complex rendering logic | Termination drawing model builder is 2000+ lines; frequent hotspot | Active development area with highest debt; needs stabilization |
| **`DbPseudos`** | MEDIUM — computed attributes used across UI | Phase/Power pseudos catch `Exception` broadly | Errors silently swallowed; bugs manifest as wrong displayed values |
| **`Cable` + `Core`** | MEDIUM — fundamental data model | Cable has cores, glands, lugs, connectors, catalogue | Domain center; changes ripple through services, repos, UI, and ETAP |
| **`ServiceFactory`** | SYSTEMIC — all services instantiated through it | Uses `Activator.CreateInstance`; returns `default(T)` on failure | Failure is silent null; any constructor change causes downstream NPE |
